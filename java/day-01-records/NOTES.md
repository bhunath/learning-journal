# Notes: Java Records

## What I remember
- Records are ideal for immutable value objects.
- The compiler generates common methods automatically.
- Fields are final and components are stored as private final values.

## What I learned
- A record cannot extend another class, but it can implement interfaces.
- Custom methods are allowed inside the record.
- Records are concise and readable for DTO / data carrier use cases.

## Questions
- How do records behave with validation logic?
- Can records be used in database mapping layers?
- When should I prefer a class over a record?
